# Core Law

TrueVision is not a raw video copier, renderer-first system, or effect stack.

TrueVision witnesses state, abstracts behavior, plans state paths, replays state, and only surfaces media at the end as proof.

```text
State first.
Behavior second.
Plan third.
Replay fourth.
Surface last.
Receipts always.
```

Generated media is a proof surface, not authority.

# Direction Model

## Forward Direction

```text
external surface
→ witnessed state
→ state events
→ behavior profile
→ reusable operator candidate
```

## Reverse Direction

```text
desired behavior
→ planned state path
→ replay state path
→ proof surface
```

## Two-Way Rule

Every serious TrueVision behavior tool should be two-way unless proven otherwise.

```text
If it can witness behavior, it should help generate behavior.
If it can generate behavior, it should explain what behavior it is generating.
```

# Forbidden Collapses

Do not collapse:

```text
state witness = raw video recording
state surface = final truth
behavior profile = copied media
TrueVideo = generic generation
proof video = evidence
effect = overlay
pretty = cosmetic
```

Correct forms:

```text
state witness = measured state from surface
state surface = visible proof of state
behavior profile = reusable transform behavior
TrueVideo = lifelike state surface lane
proof video = synthetic output for inspection
effect = behavior family
pretty = state behavior successfully surfaced
```

# Pretty Rule

Pretty is allowed.

But in TrueVision:

```text
Pretty means the proof surface visibly demonstrates correct state behavior.
```

Pretty is not decoration.

```text
Pretty is proof.
```

---

# Final Laws

```text
TrueVision does not copy media.
TrueVision witnesses state.

TrueVision does not render from vibes.
TrueVision surfaces planned state.

TrueVision does not use effects as stickers.
TrueVision uses behavior profiles.

Generated media is output, not authority.
Source truth lives in approved state logs, manifests, receipts, cell state, timing metadata, and reviewed operator packets.

A tool is only as good as how it gets used.
A behavior tool should think both directions.
```

The big upgrade here is this line:

```text
witness / profile / plan / replay / surface
```

That should become the TV language rail. It keeps real video terms usable without letting them hijack the system.
